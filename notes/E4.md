# E4 — Pixel-art frame adherence (SPEC §6)

**Question:** does the model actually emit blocky grid-aligned art at each
write size with the frame prompt? Measure blockiness **before** quantize
(E2 measured after).

**Date:** 2026-10-17. **Server:** 8189 (4080/int8). t2i arm, the E2
test-tile description with the pixel-art frame, seeds 42 + 7, sizes
{1024, 512, 256}. Script: `experiments/e4_frame_adherence.py`;
raw `images_out/e4/e4_results.json`.

Metrics (pre-quantize):
- **edges**: strong luminance steps per row/column, voted + clustered —
  position vs the expected block lines (8/16/24 art-px) and residual to
  the latent grid (W/16 px).
- **block flatness**: per-pixel RGB std inside each 8-art-px block.
- **quantize loss**: max-channel distance to the nearest *dev* palette
  color (64-color random stand-in — see finding 4).

## Results

All 6 runs: **exactly the 3 expected edge lines per axis, no extras** —
the frame prompt is obeyed structurally.

| size | edge Δ to expected (px) | residual to latent grid (px) | block std mean (max) | blocks flat (std<8) |
|---|---|---|---|---|
| 1024 s42 | −10.5 … 0 | ≤ 10.5 (one outlier) | 14.0 (48.6) | 62% |
| 1024 s7 | −3.0 … 0.8 | ≤ 3.0 | 9.7 (41.6) | 75% |
| 512 s42 | ≤ 1.5 | ≤ 1.5 | 3.4 (11.6) | **94%** |
| 512 s7 | ≤ 1.5 | ≤ 1.5 | 3.7 (13.2) | **81%** |
| 256 s42 | −5.5 … 3.5 | ≤ 5.5 (v) / ≤ 1.7 (h) | 22.5 (78.7) | 62% |
| 256 s7 | −8.1 … 2.5 | ≤ 7.9 (v) / ≤ 2.5 (h) | 27.9 (85.9) | 44% |

Per-block detail (1024 s42): the flat-color quadrants are flat (std 1–3)
but the **checker squares get texture** (std 36–49) — at 2× oversampling
the model fills the 8-art-px squares with micro-shading instead of a flat
color. At 512 the same squares are flat (std ≤ 13). At 256 the white|black
checker boundary (only 4 latents wide) smears (std up to 86).

## Findings

1. **Frame adherence is strong structurally**: exactly the requested
   blocks, no hallucinated extra edges, at every size.
2. **Flatness and alignment both peak at 512** (block std ≤ 13 everywhere,
   all edges ≤ 1.5 px). 1024 is 2× oversampled → texture in the small
   squares + occasional ~10 px edge drift; 256 is under-resolved for
   text-only generation → smearing (cf. E2's t2i 256 = 0.73 exact).
3. **512 is the best write size on every pre-quantize axis** (flatness,
   alignment) and on E2's post-quantize fidelity at ¼ the latency of
   1024. **Proposal: change the default `write_size` 1024 → 512**
   (SPEC §3 default; awaiting Felix's OK — do not flip silently).
4. **Quantize loss is ~41 mean / 51 p95 at *all* sizes and nearly all
   pixels are >16 RGB from the nearest dev-palette color.** The output
   colors are fine — the *dev palette is not*: it's a random stand-in far
   from the model's natural color space. E5 should build the real palette
   **from the model's own outputs** (the SPEC's `kmeans(init)` option),
   not by hand.
